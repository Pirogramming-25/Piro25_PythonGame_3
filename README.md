# Piro25_PythonGame_3

- 본 프로젝트는 파이썬(Python) 터미널 환경에서 실행되는 턴제(Turn-based) 기반의 미니 술게임 합치기 팀 과제입니다.
- 각 팀원이 독립된 파일(브랜치)에서 미니게임을 개발하고, 이를 메인 프로그램(`main.py`)에 통합하는 구조로 설계되었습니다.

---

## 📌 주요 요구사항 및 흐름

1. **게임 시작 및 인트로:** 타이틀 및 인트로 메시지 출력
2. **사용자 정보 입력:** 플레이어의 이름 및 소주 기준 주량(치사량) 선택 (예외 처리 포함)
3. **대결 상대 초대:** 은서, 하연, 연서, 예진, 헌도 중 랜덤으로 최대 3명의 컴퓨터 NPC 초대 (주량 랜덤 설정)
4. **메인 게임 루프:** * 플레이어와 컴퓨터가 돌아가면서 게임을 선택 및 실행 (컴퓨터는 랜덤으로 게임 선택)
   * 각 게임 결과에 따라 패배자의 마신 잔 수 누적 및 남은 치사량 실시간 업데이트
   * "exit" 입력 시 중도 종료 가능
5. **게임 오버:** 참가자 중 한 명이라도 치사량에 도달하면 전사자 메시지와 함께 프로그램 종료

## 📣 미니게임 소개

### Game 1 (더 게임 오브 데스) - 김유겸
**게임 규칙 :**
  1. 주도자가 '숫자(최소 3 이상)'를 외칩니다.
  2. 모든 플레이어는 동시에 서로를 손가락으로 지목합니다.
  3. 주도자부터 시작해 지목한 손가락을 따라 숫자를 세어나갑니다.
   
**패배/탈락 조건 :**
  - 주도자가 외친 숫자에 딱 걸린 사람이 당첨(벌주)됩니다!

---

### Game 2 (쥐를 잡자 게임) - 유채영
**게임 규칙 :**
  1. 목표 쥐 마릿수가 차기 전에는 `잡았다` 또는 `놓쳤다` 입력합니다.
  2. 목표가 다 차면 본인 차례에 반드시 `만세`를 입력합니다.

**패배/탈락 조건 :**
  - 마지막까지 `만세`를 외치지 못한 한 명이 패배합니다. 
  - 잘못된 입력/오타 발생 또는 제한 시간(5초) 초과 시 탈락합니다.

---

### Game 3 (아파트 게임) - 이지아
**게임 규칙 :**
  - 사람들이 손을 쌓아 아파트를 만든 뒤 층수를 외칩니다.

**패배/탈락 조건 :**
  - 마지막으로 외친 층수에서 맨 위에 놓이는 손의 주인이 패배합니다. 

---

### Game 4 (지하철 게임) - 강성훈
**게임 규칙 :**
  - 정해진 노선의 역 이름을 돌아가며 외칩니다.
  - 환승역을 말하면 노선을 갈아탈 수 있습니다.

**패배/탈락 조건 :**
  - 노선에 없는 역 또는 이미 나온 역을 외치는 경우 패배합니다.

---

### Game 5 (베스킨라빈스 31) - 정지민
**게임 규칙 :**
  - 한 번에 1~3개의 숫자를 말할 수 있습니다. 

**패배/탈락 조건 :**
  - 31을 말하는 사람이 패배합니다.

## 📂 프로젝트 파일 구조 (Directory Structure)

Git 충돌(Conflict)을 방지하고 코드의 독립성을 유지하기 위해 메인 로직과 미니게임을 폴더 단위로 분리합니다.

```text
Piro25_PythonGame_3
├── main.py              # 전체 게임 흐름 제어 (입력, 대결 상대 설정, 메인 턴 루프, 상태 업데이트)
└── minigames/           # 팀원별 미니게임 패키지 폴더
    ├── files/         # 지하철 게임 관련 csv 파일용 폴더
    ├── __init__.py     # 패키지 인식용 빈 파일
    ├── game1.py        # 더 게임 오브 데스 (김유겸)
    ├── game2.py        # 쥐를 잡자 게임 (유채영)
    ├── game3.py        # 아파트 게임 (이지아)
    ├── game4.py        # 지하철 게임 (강성훈)
    └── game5.py        # 베스킨라빈스 31 (정지민)
```

## 🚫 개발 및 협업 엄수 규칙 (Ground Rules)
안전한 프로젝트 통합과 Git 충돌(Conflict) 방지를 위해 다음 규칙을 반드시 준수합니다.

1. **공통 파일 수정 금지:** 공통으로 사용하는 `main.py` 파일은 개인이 임의로 수정하거나 저장소에 커밋할 수 없습니다. 
2. **독립된 개발 환경 유지:** 팀원은 오직 본인이 담당한 미니게임 파일(`minigames/game*.py`) 내부만 수정 및 작성해야 합니다.
3. **브랜치 보호:** `main` 및 `develop` 브랜치로의 직접적인 `push`는 엄격히 금지됩니다. 모든 변경 사항은 반드시 개인 브랜치에서 작업 후 `Pull Request(PR)`를 통해서만 반영되어야 합니다.

## 🌿 Git 브랜치 네이밍 규칙 (Branch Naming Convention)

팀원 간 브랜치 이름의 형식을 통일하여 관리합니다. 모든 브랜치는 영문 소문자를 사용하며, 단어 구분은 하이픈(`-`)으로 합니다.

* **형식:** `feat/game-[게임명]`
* **브랜치 이름 예시:**
  * 369 개발 브랜치: `feat/game-369`
  * 좋아 게임 개발 브랜치: `feat/game-like`
